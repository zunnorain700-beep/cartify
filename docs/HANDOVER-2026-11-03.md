# Cartify — session handover, 3 November 2026

Work ran from 02:44 to 12:00 PKT. 55 commits, all pushed to `origin/master`.
The phone was used for real testing throughout (build, install, tap-through).

## What the session was about

Three things, in order of how much they mattered:

1. **Save the right recording.** Early builds would happily download a live version or a
   remix when the studio track was asked for, and could drop to a low bitrate. That is
   the worst failure a downloader can have, because it looks like success.
2. **Make it pleasant and fast.** Search became the home screen, playback got a proper
   player, downloads went from ~16s to ~4s per track, and failures got readable reasons.
3. **Make it survive real use.** Rate limits, dropped connections, phone calls, restarts
   and a full library all had to behave.

## The changes worth knowing about

### Getting the right file

- **Scored matching instead of first-hit.** Each candidate is scored on title, artist and
  duration. *Benefit:* the studio recording wins. *Cost:* a rare track with only odd
  uploads may be skipped rather than saved wrongly.
- **A variant guard that cannot be bypassed.** If the upload says *live*, *remix*,
  *karaoke* or *instrumental* and the user did not ask for it, the match is rejected
  outright — even when the title and artist look perfect. *Benefit:* no more silent
  substitutions. *Cost:* slightly fewer matches for obscure songs.
- **No downgrading.** Quality is selectable and defaults to Best (V0). *Benefit:* you get
  the master audio. *Cost:* larger files.
- **Title normalisation.** Catalogue suffixes like `(From "Film")`, `(Deluxe Edition)` and
  `(feat. X)` are stripped before comparing. *Benefit:* Spotify titles match real uploads.

### Speed and reliability

- **Parallel fragments sized to the link.** *Benefit:* per-track time fell from ~16s to
  ~4s. *Cost:* more connections, which is why retries exist.
- **Retries with a different client** on format-miss, dropped connection or zero bytes.
  *Benefit:* transient failures heal themselves. *Cost:* a genuinely unavailable track
  takes a little longer to be declared failed.
- **Spotify throttling handled.** Requests are gated, 429s back off progressively and the
  wait is stated in the status line. *Benefit:* a long playlist no longer dies halfway.
- **Caching.** Spotify collections are cached ten minutes, artwork on disk, search results
  briefly. *Benefit:* reopening the app is instant and does not re-hit the network.

### The app itself

- **Search is the home tab**, with recommended music and recent searches as chips.
  *Benefit:* you can find and download without leaving the first screen.
- **Spotify-style shelves** for albums and recommendations.
- **A real player** with artwork, seek, queue, sleep timer (15/30/45/60), shuffle and
  repeat remembered across restarts, plus lyrics that scroll.
- **Offline library** grouped by artist, searchable, with multi-select, drag reorder,
  playlists, and `.m3u` export.
- **Recently played leads the home screen.** *Benefit:* the app opens on your own
  listening rather than a stranger's chart.
- **Audio focus.** *Benefit:* a call or another player pauses the music; a notification
  only ducks it.
- **Undo for delete**, held for ten seconds. *Benefit:* a mis-tap is recoverable.
- **Plain-language errors.** "No internet connection" instead of a DNS dump; a short
  reason on a failed row instead of raw downloader output.

## Decisions taken that are worth knowing

- A refused audio-focus request still plays. Focus is a courtesy to other apps, not a
  lock on the speakers; silently not playing would be worse.
- Recently played is read before the public chart, and the chart is only fetched when
  there is no history. Both fill the same rows, so the order is the decision.
- History is recorded inside the player's prepared callback, not at each call site,
  because every path (row, shuffle, auto-advance, notification) goes through it.
- The multi-user check found `Music/Cartify` is a shared public path, but MediaStore
  scopes it per user on API 29+ and the legacy branch only runs pre-Q. Left as is rather
  than adding complexity for a case the platform already handles.
